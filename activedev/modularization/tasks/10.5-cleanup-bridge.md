## Motivation

`T10.5` starts immediately after `T10` and closes the cleanup bridge. It owns the leftover cross-lane work from `T01`–`T09` that still needs shared contract ownership after `T10` finishes its owned implementation: migrate shared browser contracts off temporary `app.js` seams, retire the documented bridge anchors that `T10` left behind, close any explicitly handed-off cleanup debt that still spans lanes, and unblock `T11` using targeted validation only.

`T10.5` is **not** a second monolith-shrink bucket and it is **not** the broad certification gate. If a cleanup item is fully owned by `T10`, finish it in `T10` instead of pushing it here.

## Leftover work by source task

### 1. Shared browser-contract migration unlocked by `T10`

`T10` should hand this task an explicit bridge-anchor list. `T10.5` retires those anchors by migrating the shared browser contract files that still source-assert `app.js` internals.

#### a. `tests/browser/test_project_lifecycle_contracts.py`

Still source-asserts `wireEvents()` project/open/import handlers. Update assertions to target the extracted module boundaries (`lib/shell-runtime.js` and `panes/project-pane.js`) instead of scanning `app.js` for pre-extraction function text.

#### b. `tests/browser/test_merge_export_contracts.py`

Still source-asserts merge/export ordering anchors and `wireEvents()` export behavior. Update to assert the delegate wrappers in `app.js` and the real implementations in `lib/shell-runtime.js` / `panes/export-pane.js` / `panes/merge-pane.js`.

#### c. `tests/browser/test_overlay_review_contracts.py`

Still source-asserts wrapper seams that remain in `app.js` (e.g., `readOverlayPayload()`, overlay render entry points, review text-box delegates). Update to follow the extracted module boundaries.

#### d. `tests/browser/test_scoring_metrics_contracts.py`

Still source-asserts scoring/metrics wrapper seams in `app.js`. Update to point at `panes/scoring-pane.js`, `panes/settings-pane.js`, `panes/metrics-pane.js`.

#### e. `tests/browser/test_timing_waveform_contracts.py`

Still source-asserts timing/waveform wrapper seams in `app.js`. Update to point at the component and pane module boundaries.

#### f. Legacy runtime test patterns

Some tests still use bare globals exposed by `installLegacyGlobalCompat()` (e.g., `activeTool`, `state`, `selectedShotId`, `createNewProject()`, `setPopupBubbles()`, `renderTextBoxEditors()`). Verify each usage and replace with module-backed accessors where possible, or document why the global bridge must persist for that specific test.

#### g. PractiScore guardrail

If project-pane bridge seams move, also review `tests/browser/test_practiscore_session_api.py` and `tests/browser/test_practiscore_sync_controller.py` so the PractiScore contract does not keep stale `app.js` assumptions by accident.

### 2. Residual `T01`–`T09` cleanup debt that may still need bridge ownership

These items should be closed in `T10` whenever they are fully owned there. `T10.5` only picks them up if the `T10` handoff proof explicitly says they still require shared contract ownership or bridge-wide edits.

#### a. Centralize same-project draft/refresh preservation

The draft-preservation pattern was implemented independently across T05, T09D, and T09E to protect merge, export, overlay, popup/template, and markers/timing drafts from being clobbered by late remote-state echos. This logic currently lives in `lib/api.js` (stale-response domain suppression) plus per-pane flush/keepalive helpers in `app.js`. Consolidate into a shared `lib/draft-consolidator.js` or a dedicated seam in `lib/api.js`.

#### b. Centralize app-level debounce/flush seams

Several panes (scoring, settings, export) still route their `schedule*Apply()` through `app.js` wrappers that own the shared debounce/cancel/keepalive sequencing. The panes already own the `read*Payload()` and apply logic; the debounce/flush orchestration can move into a shared backbone module so `app.js` is not the sole coordinator.

#### c. Clean up minor documentation lint

T01 noted pre-existing markdown-lint findings in `activedev/modular.md`. T02 noted the same in `docs/tests/TEST_SUITE_GUIDE.md`. These are cosmetic but should be resolved before the final certification gate (T12).

#### d. `data-table.js` deferral status

T06 intentionally deferred creating `data-table.js` because no real multi-area reuse was established. Re-evaluate during cleanup — if a consolidated helper would genuinely simplify the remaining `app.js` shell, create it now. Otherwise mark as permanently waived.
